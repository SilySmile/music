# 本地强对齐：部署与播放器配置

本目录包含启动脚本、服务端、配置和本文档。原模型继续保存在 **`E:\work\model\Qwen3-ForcedAligner-0.6B`**，不移动、不改写、不重复下载。部署环境、缓存、日志与临时文件集中在本目录 `runtime/`，不安装进日常 Python 环境。

当前电脑检查结果：RTX 4060 Laptop 8GB 显存、约 32GB 内存；**WSL 尚未安装**。播放器接口和模拟测试可验证，但本机尚不能直接运行 Linux vLLM，必须先完成首次准备。尚未在本机完成真实 GPU 推理测试。

## 第一次准备

1. 双击 **`01-首次准备.cmd`**。Windows 权限请求用于安装 WSL 组件。脚本不自动重启；若 Windows 要求重启，请自己重启后再次双击同一个脚本。
2. 后续准备会下载并核对 Ubuntu 官方镜像，创建专用 WSL2 环境 **`XianqijiAligner`**，虚拟磁盘放在 `runtime/wsl/`。只操作这个专用环境，不关闭或替换其他项目的 Linux 环境。
3. 安装隔离的 vLLM、CUDA/PyTorch 依赖和音频工具，首次需要网络及数 GB 到十余 GB 磁盘空间。模型仍读取原目录；准备时可看到下载进度。
4. 看到“准备完成”后无需重复安装。若缺少 CPU 虚拟化支持，须在 BIOS/Windows 完成虚拟化设置，脚本会停止并提示。

**`05-检查环境.cmd`** 只检查，不安装组件。

## 需要时启动，不用时停止

- **`02-启动模型.cmd`**：启动专用模型服务，等待“模型已就绪”。重复启动不会加载第二份模型。首次加载可能编译内核，日志在 `runtime/logs/server.log`。
- **`04-查看状态.cmd`**：查看模型是否就绪、资源是否充足、正在处理多少首歌曲。
- **`03-停止模型.cmd`**：停止专用 Linux 环境及推理进程，释放模型显存；不终止其他 WSL 环境。

不设置开机自启，也不随播放器启动模型。默认 **10 分钟没有音频对齐请求**时服务退出；连接检查不延长这个时间。之后需要时再双击启动。自动处理发现服务停止时只等待，不反复启动模型。

## 地址、模型名称、密钥从哪里来

本机已生成 **`runtime/播放器连接配置.json`**，首次准备也会生成或刷新它。直接导入，不需要向第三方申请密钥。

| 播放器配置项 | 默认值 / 来源 |
| --- | --- |
| 强对齐服务地址 | `http://127.0.0.1:8765/v1`，来自本机服务的端口配置 |
| 强对齐模型名称 | `qwen3-forced-aligner`，服务对外公布的别名，不是磁盘路径 |
| 本地服务密钥 | 本机随机生成，位于上述连接配置的 `key` 字段，终端与日志不打印 |

模型路径单独写在 `runtime/service.json` 的 `model_path`，默认正是已下载的目录。更改端口、别名或资源参数后先停止服务，修改文件，再重新启动；再次运行首次准备会刷新连接配置并保留已有密钥。

播放器连接步骤：

1. 偏好设置 → AI 配置 → 逐字时间生成方式，选择 **“本地强对齐（音频 + 原歌词）”**。
2. 点 **“导入本地强对齐配置”**，选 `runtime/播放器连接配置.json`。
3. 启动模型后点 **“测试强对齐连接”**，应显示模型别名和可用并发数。
4. 选择手动或自动，再点 **“保存 AI 配置”**。强对齐密钥独立于翻译密钥，播放器使用设备系统加密保存，不写进音乐包或明文偏好设置。

连接配置本身包含本地密钥，请留在本机。`runtime/` 已忽略，不提交或发布。服务默认只监听回环地址，普通 HTTP 仅限本机，无需域名与证书。手机的 `127.0.0.1` 指手机自身；若将来要从手机访问电脑，须另行配置可访问的 HTTPS 服务地址。

## 手动与自动

**手动（默认）**：歌词设置中可生成本句、补齐整首缺失时间，或重新生成整首已有时间。旧聊天估算不准时用“重新生成”。新结果先进入草稿，试听后“保存歌词时间”才替换增强 LRC 和曲库。失败、取消、未匹配保留旧数据，中文保留。

**自动（桌面端，主动勾选并保存）**：服务启动且资源充足时，处理本地歌曲缺失的逐字时间和带“AI 估算时间”标记的旧结果。已有有效实测逐字时间跳过。自动结果通过原文、字数、顺序、不重叠和时间边界校验后直接保存；不匹配句子保留原数据。失败按音乐库、歌曲和模型记录，防止不停重试；可点“重试本地强对齐失败项”。原歌词或模型变化后重新核对。

打开歌词编辑、导入或切换曲库时自动队列暂停；恢复条件满足后继续。退出或关闭自动处理取消未保存结果。关闭自动处理不等于关闭模型，释放显存请运行停止脚本或等待空闲退出。

## 并发与资源保护

默认针对这台 8GB 显存电脑：

| 限制 | 默认 |
| --- | --- |
| 并发歌曲 | 最多 2 首，可在播放器改为 1 首 |
| GPU 微批次 | 最多 2 个片段，共用一个模型，不复制多份模型 |
| vLLM 显存预算 | 45% |
| 服务 CPU 硬限额 | 约 6 个逻辑核的算力，较低调度优先级 |
| 服务内存硬限额 | 8GB，超限停止服务 |
| 音频解码 | 同时 1 份，每首最多 20 分钟、上传不超过 24MB |
| 单句对齐范围 | 最多 60 秒；超出时先设本句唱完时间再重试 |
| 暂停接新任务 | 空闲显存少于 1.5GB、可用内存少于 4GB、CPU 超过 85% 或 GPU 达到 82°C |

启动前还会检查 Windows 可用内存至少 12GB，给受限服务之外预留余量，且空闲显存能容纳预算并留下余量。播放器通过系统接口同时检查 Windows 主机的可用内存和 CPU，不只看 WSL 内部资源。

客户端与服务都有并发上限，不一次解码整库。资源紧张时不接新推理任务，播放器稍后检查；已执行的短批次不强杀 CUDA 内核。显存溢出或引擎异常后停止接任务，避免 OOM 重试风暴；关闭其他占 GPU 软件后再启动。预算和保护降低卡顿风险，不能保证其他软件抢显存时绝无峰值。服务失败不覆盖已保存的音乐和歌词。

边玩游戏边听歌时选择并发 1，或停止模型；集中处理歌曲时再启动并发 2。

## 间奏与准确性

服务接收**原音频和已确认原歌词**，使用模型时间输出，不凭空把一组词均分成“实测”字时间。使用原句开始到下一句开始的音频范围；有本次手动唱完时间时遵守它。末字结束单独保存，后续间奏不被平均分摊给歌词。

模型主要针对语音训练，复杂伴奏、合唱、拖音或歌词版本不对仍可能要校准。强对齐不是人声分离，也不能证明每个字确实唱了；缺词或纯音乐片段可能产生不可靠结果。无效、重叠、倒序或零时长被拒绝并保留原数据。普通 LRC 整句时间应大致对应歌曲；纯文本需先设置句子开始时间。

## 目录与故障排查

```text
local-aligner/
  README.md                   本文档
  01-首次准备.cmd
  02-启动模型.cmd
  03-停止模型.cmd
  04-查看状态.cmd
  05-检查环境.cmd
  config.example.json         默认设置，无密钥
  requirements.txt            固定兼容版本
  scripts/                    Windows 与 Linux 管理脚本
  src/                        对齐接口与校验逻辑
  tests/                      隔离测试
  runtime/                    本机生成，不提交、不发布
    service.json              路径、资源参数、本地密钥
    播放器连接配置.json       导入播放器的连接信息
    wsl/                      专用 Linux 虚拟磁盘，含环境与缓存
    downloads/                首次安装镜像
    logs/                     启动与安装日志
    tmp/                      请求临时音频，正常结束自动清理
```

- 连接失败：先启动服务。输入地址不会自动启动模型。
- 401：重新导入本机连接配置，不使用翻译服务的密钥。
- 模型名不匹配：以连接配置的 `model` 为准，不填 `E:\...` 路径。
- 503/资源紧张：查看状态，关闭占显存的软件或降低并发，重启前先停止旧服务。
- 启动超时：看 `runtime/logs/server.log`，检查 WSL、GPU、依赖和显存；脚本不再启动第二份模型。
- 单句区间过长：设置实际唱完时间，再生成本句。
- 自动未重试：问题解决后点“重试本地强对齐失败项”。
