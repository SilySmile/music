# 本地强对齐：部署与播放器配置

本目录包含启动脚本、服务端、配置和本文档。原模型继续保存在 **`E:\work\model\Qwen3-ForcedAligner-0.6B`**，不移动、不改写、不重复下载。部署环境、缓存、日志与临时文件集中在本目录 `runtime/`，不安装进日常 Python 环境。

本机实际部署目录统一为 **`E:\work\model\local-aligner`**，启动、停止脚本也在这里。播放器项目中的 `local-aligner` 是指向此目录的链接，用于保留源码管理与发布检查入口，实际文件只有一份。连接配置位于 `E:\work\model\local-aligner\runtime\播放器连接配置.json`。

当前方案为 **Windows 原生 PyTorch / Transformers + 官方 qwen-asr**，使用本机 RTX 4060 Laptop 8GB 显卡与约 32GB 内存。无需 WSL、Linux、虚拟机或单独安装 CUDA Toolkit，不安装 FlashAttention，也不修改系统 Python 的依赖。

已在这台电脑完成真实 CUDA 推理：中文合成语音的逐字时间、约 1.5 秒句内停顿、句尾静音与两路并发请求均通过；另测试两个 59 秒片段组成的批次，CUDA 分配峰值约 2.4GB（不含其他软件、驱动及上下文）。这验证部署与资源控制可用，歌曲中的伴奏、合唱和拖音仍需试听判断准确度。

## 第一次准备

1. 本机已有 Windows 64 位 Python 3.12。其他电脑需要先安装 [Python 3.12](https://www.python.org/downloads/release/python-31210/)（也支持 3.11），并更新 NVIDIA 显卡驱动。
2. 双击 **`01-首次准备.cmd`**，脚本创建 `runtime/native-env/` 独立环境，安装固定版本的 CUDA PyTorch、官方 qwen-asr、接口与音频依赖。首次联网下载数 GB，解压与缓存需要额外磁盘空间；日志在 `runtime/logs/prepare.log`。
3. 看到“准备完成”后无需重复安装。模型直接读取已有权重，不重复下载；无需管理员权限和 Windows 重启。

**`05-检查环境.cmd`** 只检查，不安装组件。

## 需要时启动，不用时停止

- **`02-启动模型.cmd`**：启动本机 CUDA 模型服务，等待“模型已就绪”。重复启动不会加载第二份模型。日志在 `runtime/logs/server.log` 与 `server-error.log`。
- **`04-查看状态.cmd`**：查看模型是否就绪、资源是否充足、正在处理多少首歌曲。
- **`03-停止模型.cmd`**：请求服务退出，必要时只结束经过 PID、创建时间、脚本路径及启动标识核对的本目录模型。Windows 作业对象负责回收音频解码子进程，释放模型显存。

不设置开机自启，也不随播放器启动模型。默认 **10 分钟没有音频对齐请求**时服务退出；连接检查不延长这个时间。之后需要时再双击启动。自动处理发现服务停止时只等待，不反复启动模型。

看到就绪提示后可以关闭启动窗口。模型在隐藏的独立 Windows 进程中运行，空闲退出或手动停止后释放资源。

## 地址、模型名称、密钥从哪里来

本机已生成 **`runtime/播放器连接配置.json`**，首次准备也会生成或刷新它。直接导入，不需要向第三方申请密钥。

| 播放器配置项 | 默认值 / 来源 |
| --- | --- |
| 强对齐服务地址 | `http://127.0.0.1:8765/v1`，来自本机服务的端口配置 |
| 强对齐模型名称 | `qwen3-forced-aligner`，服务对外公布的别名，不是磁盘路径 |
| 本地服务密钥 | 本机随机生成，位于上述连接配置的 `key` 字段，终端与日志不打印 |

模型路径单独写在 `runtime/service.json` 的 `model_path`，默认正是已下载的目录。更改端口、别名或资源参数后先停止服务，修改文件，再重新启动；再次运行首次准备会刷新连接配置并保留已有密钥。

播放器连接步骤：

1. 偏好设置 → AI 配置 → 逐字时间生成方式，选择 **“本地强对齐（音频 + 原歌词）”**。
2. 点 **“导入本地强对齐配置”**，选 `runtime/播放器连接配置.json`。
3. 启动模型后点 **“测试强对齐连接”**，应显示模型别名和可用并发数。
4. 选择手动或自动，再点 **“保存 AI 配置”**。强对齐密钥独立于翻译密钥，播放器使用设备系统加密保存，不写进音乐包或明文偏好设置。

连接配置本身包含本地密钥，请留在本机。`runtime/` 已忽略，不提交或发布。服务默认只监听回环地址，普通 HTTP 仅限本机，无需域名与证书。手机的 `127.0.0.1` 指手机自身；若将来要从手机访问电脑，须另行配置可访问的 HTTPS 服务地址。

## 手动与自动

**手动（默认）**：歌词设置中可生成本句、补齐整首缺失时间，或重新生成整首已有时间。旧聊天估算不准时用“重新生成”。新结果先进入草稿，试听后“保存歌词时间”才替换增强 LRC 和曲库。失败、取消、未匹配保留旧数据，中文保留。

**自动（桌面端，主动勾选并保存）**：服务启动且资源充足时，处理本地歌曲缺失的逐字时间和带“AI 估算时间”标记的旧结果。已有有效实测逐字时间跳过。自动结果通过原文、字数、顺序、不重叠和时间边界校验后直接保存；不匹配句子保留原数据。失败按音乐库、歌曲和模型记录，防止不停重试；可点“重试本地强对齐失败项”。原歌词或模型变化后重新核对。

打开歌词编辑、导入或切换曲库时自动队列暂停；恢复条件满足后继续。退出或关闭自动处理取消未保存结果。关闭自动处理不等于关闭模型，释放显存请运行停止脚本或等待空闲退出。

## 并发与资源保护

默认针对这台 8GB 显存电脑：

| 限制 | 默认 |
| --- | --- |
| 并发歌曲 | 最多 2 首，可在播放器改为 1 首 |
| GPU 微批次 | 最多 2 个片段，共用一个模型，不复制多份模型 |
| PyTorch CUDA 分配器显存预算 | 最高 45%，按空闲显存自动下调；不含驱动与 CUDA 上下文本身 |
| 服务 CPU 硬限额 | 约 6 个逻辑核的算力，较低调度优先级 |
| 服务内存硬限额 | 8GB，超限停止服务 |
| 音频解码 | 同时 1 份，每首最多 20 分钟、上传不超过 24MB |
| 单句对齐范围 | 最多 60 秒；超出时先设本句唱完时间再重试 |
| 暂停接新任务 | 空闲显存少于 1.5GB、可用内存少于 4GB、CPU 超过 85% 或 GPU 达到 82°C |

启动前还会检查 Windows 可用内存至少 12GB，给受限服务之外预留余量；显存须至少能容纳总显存 30% 的加载预算，并留下 1.5GB 余量。实际分配器上限按当时空闲量在 30%–45% 之间下调。播放器与原生服务都检查 Windows 主机的可用内存和 CPU。

客户端与服务都有并发上限，不一次解码整库。资源紧张时不接新推理任务，播放器稍后检查；已执行的短批次不强杀 CUDA 内核。显存溢出或引擎异常后停止接任务，避免 OOM 重试风暴；关闭其他占 GPU 软件后再启动。预算和保护降低卡顿风险，不能保证其他软件抢显存时绝无峰值。服务失败不覆盖已保存的音乐和歌词。

边玩游戏边听歌时选择并发 1，或停止模型；集中处理歌曲时再启动并发 2。

## 间奏与准确性

服务接收**原音频和已确认原歌词**，使用模型时间输出，不凭空把一组词均分成“实测”字时间。使用原句开始到下一句开始的音频范围；有本次手动唱完时间时遵守它。末字结束单独保存，后续间奏不被平均分摊给歌词。

保存结果使用现有的**增强 LRC 歌词文本**，同时更新曲库中的逐字时间，不额外散落一批 JSON 文件。例如：

```lrc
[00:01.000][x-end:00:03.960]<00:01.000>你<00:01.800><00:03.000>好<00:03.960>
[00:07.000]下一句
```

这个例子中“你”在 1.00–1.80 秒唱，“好”在 3.00–3.96 秒唱；字间停顿和 3.96–7.00 秒的间奏都保留。示例仅说明格式，不是对真实歌曲的测量结果。

每首都会检查全部待处理句子，“两句”是 GPU 小批次，不是每首的句数上限。播放器显示当前歌曲已检查、通过的句数；完成后显示本轮生成和未通过的句数。自动模式跳过已有有效逐字时间，手动“重新生成整首”才会重算已有时间。

模型原始最高分时间有效时直接保留。出现时间交叉或零时长时，使用同一次推理的时间分类分数，在原句范围内寻找符合字序、每字时长为正的最高分路径；各端点调整最多 0.8 秒、单点分数差不超过 3、平均分数差不超过 0.8。这些是控制修正范围的内部阈值，不代表准确率或概率。没有足够模型分数支持的结果保留原时间并显示原因；不把字平均铺满原句，也不把末字拉到下一句。

本机《慕夏》51 个待处理句的只读测试中，原解码通过 25 句，分数约束解码通过 49 句、2 句拒绝。新服务实际 HTTP 请求约 3 秒（模型已加载）；另一次包含模型加载的独立诊断约 13 秒。这是格式和边界校验通过数，并非经人工听辨的逐字准确率，其他歌曲耗时与效果会不同。资源检查共享最多 1 秒的缓存，减少重复启动显卡查询的开销，仍保留原并发和资源保护。播放器升级后，旧失败记录允许重新尝试一次；仍失败的句子不持续重跑，可主动点重试。

模型主要针对语音训练，复杂伴奏、合唱、拖音或歌词版本不对仍可能要校准。强对齐不是人声分离，也不能证明每个字确实唱了；缺词或纯音乐片段可能产生不可靠结果。普通 LRC 整句时间应大致对应歌曲；纯文本需先设置句子开始时间。

## 目录与故障排查

```text
local-aligner/
  README.md                   本文档
  01-首次准备.cmd
  02-启动模型.cmd
  03-停止模型.cmd
  04-查看状态.cmd
  05-检查环境.cmd
  config.example.json         默认设置，无密钥
  requirements.txt            固定兼容版本
  scripts/                    Windows 原生管理脚本
  src/                        对齐接口与校验逻辑
  tests/                      隔离测试
  runtime/                    本机生成，不提交、不发布
    service.json              路径、资源参数、本地密钥
    播放器连接配置.json       导入播放器的连接信息
    native-env/               独立 Windows Python 环境，含 CUDA 与音频工具
    cache/                    Python 安装包与模型工具缓存
    downloads/                下载与验证用文件
    logs/                     启动与安装日志
    tmp/                      请求临时音频，正常结束自动清理
```

- 连接失败：先启动服务。输入地址不会自动启动模型。
- 旧 WSL 超时提示：当前脚本已经改为 Windows 原生，不会查询或安装 WSL。请从本目录的五个编号脚本运行。
- 401：重新导入本机连接配置，不使用翻译服务的密钥。
- 模型名不匹配：以连接配置的 `model` 为准，不填 `E:\...` 路径。
- 503/资源紧张：查看状态，关闭占显存的软件或降低并发，重启前先停止旧服务。
- 启动超时：看 `runtime/logs/server-error.log`，检查 NVIDIA 驱动、依赖和显存；脚本不再启动第二份模型。缺少依赖时重新运行首次准备。
- 单句区间过长：设置实际唱完时间，再生成本句。
- 自动未重试：问题解决后点“重试本地强对齐失败项”。
