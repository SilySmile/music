# 一键发布 PC / 安卓新版

这是开发者电脑上的发布工具，不是普通用户在播放器里上传安装包。安装包内不带发布私钥、SSH 密码或 GitHub 授权。源码入口：项目根目录 `一键发布.cmd`（双击），或 PowerShell `一键发布.ps1`。

## 每次发布只需准备

1. 更新 `package.json`、`package-lock.json`、安卓 `android/app/build.gradle` 的版本；安卓 `versionCode` 也必须增加。不自动更改版本。
2. 人工审核、提交并推送源码到 `origin/main`。工作区必须干净，HEAD 必须与远端 main 一致；工具不擅自提交、推送或删除文件。
3. 在 `docs/releases/v版本.md` 编写并提交更新说明，打包时自动复制到 `release/v版本/update-notes.txt`；已有该 TXT 时以 TXT 为准。安装包和私钥不加入 Git。
4. 双击 `一键发布.cmd`，确认目标版本 / 地址，输入 `PUBLISH 版本号`。例如 `PUBLISH 1.0.4`，其他输入取消。

全流程自动执行：预检查 → 前端单元测试 / 发布工具测试 / 服务端测试 → Web 构建 → 安卓同步 / Release 构建 / JVM 测试 / 原签名 → PC 安装包与便携包 → 独立测试曲库的 Electron / 安卓目录模拟 / 便携启动回归 → RSA 签名清单与 SHA256SUMS → GitHub 草稿上传并核对 SHA-256 → 受限账号发布更新服务器 → 完整回读三个安装包校验哈希与 Range → GitHub 草稿公开。

GitHub 发布包含 PC 安装包、便携包、APK、在线曲库部署包、`manifest.json`、`SHA256SUMS.txt`、更新说明。哈希字段遵循 [GitHub 官方 Release Assets API](https://docs.github.com/en/rest/releases/assets?apiVersion=2022-11-28)。若 GitHub 未提供哈希，工具停止而不忽略校验。

## 先给手机实测，不立即发布

```powershell
.\一键发布.ps1 -Mode check       # 只做离线工具 / 版本检查，不联网、不构建、不上传
.\一键发布.ps1 -Mode prepare     # 全部构建和本机回归，仅留本地包
.\一键发布.ps1 -Mode resume      # 手机测试通过后，校验原文件再续发
```

也可使用 `npm run publish:check`、`npm run publish:prepare`、`npm run publish:all`、`npm run publish:resume`。运行 npm 时应使用 Node.js 22.12+。本机已配置的 JDK / SDK / Gradle / Playwright / Python 自动查找，也支持 `JAVA_HOME`、`ANDROID_HOME`、`GRADLE_HOME`、`PLAYWRIGHT_MODULE`、`PYTHON_EXE` 覆盖。

手机锁屏后台连播、文件授权和系统覆盖安装仍需要真机确认。自动检查中的安卓 UI 是模拟授权，`androidTested` 检查点字段仅表示 JVM / 构建自动验证通过，不表示手机已实测。是否公开发布由维护者确认；没有设备时不可把自动测试说成真机验证。

## 出错和续发

Windows 入口已避免在批处理执行中途切换代码页，批处理内容仅含 ASCII 命令，实际逻辑由 `scripts/release-launcher.ps1` 处理。遇到旧入口的“不是内部或外部命令”报错时，关闭旧窗口，重新双击更新后的根目录 `一键发布.cmd`；也可以运行 `.\一键发布.ps1 -Mode check` 先离线检查，无需重新安装播放器。

- 失败立即停止后续步骤。已有 `release/v版本/publish-state.json` 时，使用 `resume`，核对相同源码、更新说明、签名、三个安装包与 TAR 后继续，不重新打包或重签。
- 成功上传且哈希相同的 GitHub 资源复用，不覆盖同名不同内容。一个大文件中途失败不能字节续传；服务器 TAR 同样会重新发送。GitHub 留下未完成 / `starter` 同名资源时，需维护者在草稿中核实并手动移除该未完成资源后重试，工具不自动删除资源。
- 没有检查点表示尚未进入上传阶段，可以修复原因后重试。检查点建立后若要修改源码，请提升版本，不使用新包替换旧版本。已公开版本不可回退或覆盖。
- 两个发布目标没有分布式事务：更新服务器成功、GitHub 公开失败时，服务器仍已上线；不要声称整体回滚。修复网络 / 权限后 `resume` 补完 GitHub。
- `.release-staging/publish.lock` 防止并行发布。正常退出会移除；断电 / 强制结束后先核实其中 PID 对应的发布进程确已停止，再**仅手动删除这个锁文件**，不删除 staging、检查点、密钥或 Data。
- 日志和检查点不存访问凭据。不要把完整本机配置、音乐库、私钥压缩后当 Release 资源上传。
- 构建前检查目标版本目录：包含 Data、音乐库、原始歌曲 / LRC、密钥或目录链接时拒绝覆盖，避免 electron-builder 清理实际曲库。不要把正在使用的播放器和音乐库放在构建输出目录。

## 首次换电脑

先安装 Node.js、依赖、JDK 21、Android SDK、Gradle、Python、Playwright 与可用浏览器；执行 `npm ci`。安全恢复原维护者的 `.release-keys` 备份（安卓原证书与口令、更新 RSA 私钥、受限发布 SSH 私钥与已核实的 `known_hosts` / `publisher.json`）；再通过 Git Credential Manager 登录有 Release 写入权限的 GitHub 账号。

脚本不自动生成、替换或轮换已有身份，不要求 root 密码，SSH 只使用原受限发布账号。缺少原签名库时不能给已有客户端发布可覆盖更新。首次克隆还需正确配置本机 `android/local.properties`。换发布服务器时应先独立完成 HTTPS 与受限账号部署，核实主机公钥，再修改发布配置，不能通过关闭校验凑合发布。
