# 构建与发布

当前版本为 v1.0.1。仓库包含 Windows Electron、安卓 Capacitor、React 界面、测试与更新服务部署脚本，不包含用户音乐、应用 Data、安装包、服务器登录凭据或任何签名私钥。本机交付 / 部署记录不随源码上传。

## 本地开发

需要 Node.js 22.12+；安卓额外需要 JDK 21、Android SDK 36。将 JAVA_HOME、ANDROID_HOME 指向本机运行环境，安卓 local.properties 使用本机 SDK 路径，不要提交该文件。

```powershell
npm ci
npm test
npm run dev
```

Windows 客户端开发：`npm run desktop`。构建前端：`npm run build`。构建会同步更新服务的公开信任配置到安卓资源，不会生成或复制私钥。

## Windows

```powershell
npm run build
npx electron-builder --win nsis portable --x64 --config.directories.output=release/v1.0.1
```

产物为安装包 `Xianqiji-Setup-1.0.1-x64.exe` 和便携包 `Xianqiji-1.0.1-x64.exe`。发行安装包未配置商业 Authenticode 证书，不能把更新清单的 RSA 签名当作 Windows 商业代码签名。

正式运行会使用安装目录 / 便携启动器旁的 Data；切勿在清理构建目录时误删其中实际使用的音乐库。升级前从托盘退出旧版，不同时运行两个播放器操作同一个库。

## 安卓

```powershell
npm run android:sync
cd android
.\gradlew.bat assembleRelease testReleaseUnitTest
cd ..
npm run android:sign-release
```

Release 构建关闭调试。签名脚本需要本机受限的 `.release-keys/android-release.p12` 与 `android-keystore-password.txt`；它们不在 Git 仓库中。原发行版为兼容现有客户端，仍使用早期开发证书身份；该证书不是商店发行方案。缺失密钥时应由原维护者恢复加密备份，不要生成其他证书冒充原版，否则已有客户端无法覆盖升级。

独立派生项目应自行规划应用包名、长期签名证书、更新信任公钥及服务地址；不要沿用原发布者的更新身份来给自己的安装包签名。`build/android-signing.json` 只有证书指纹和别名，不包含私钥，修改指纹并不会取得对应身份。签名和客户端迁移规则见 [Android 官方签名文档](https://developer.android.com/studio/publish/app-signing)。

构建 / JVM 测试不能代替手机实测；锁屏连播、省电策略、文件选择、Keystore 与系统覆盖安装需要实际设备验证。

## 自托管更新

- `updates/public.json` 是客户端的公开更新地址及 RSA 公钥；用户可在设置中改填 HTTPS 域名，但新服务器必须提供同一发布者签名的清单。
- 更新清单为 RSA-SHA256 签名的完整 JSON 载荷，安装包还验证大小和 SHA-256；安卓额外验证包名、递增版本号及 APK 签名一致性。
- `deployment/` 提供 Nginx、证书续期、受限发布账号及发布校验入口。部署前按自己的系统、域名、网络和防火墙调整；不能直接覆盖已有业务或关闭 TLS 校验。
- 默认服务地址供原发行版使用，不代表仓库克隆者获得发布权限、服务器管理权限或免费托管承诺。

原维护者本机发布流程：

1. 增加 package.json / package-lock.json、侧栏 / 关于和安卓版本，versionCode 也必须增加。
2. 运行测试、构建并验证三个平台包，填写 `release/v版本/update-notes.txt`。
3. `npm run release:create` 使用本机离线 RSA 私钥签名并生成 TAR；该私钥不在服务器或客户端中。
4. `npm run release:publish` 使用受限 SSH 发布账号和固定主机公钥上传，再通过公网 HTTPS 验签。
5. 把 staging 的 manifest.json 复制到正式版目录，生成 SHA256SUMS.txt，运行 `node scripts/verify-release.cjs` 和 `node scripts/check-published-updates.cjs`。

清单有效期 180 天，需要定期刷新。相同路径的已发布文件不可替换成不同内容；有修复时提高版本号，不回退版本。发布密钥、SSH 私钥、Android 签名库及口令都应离线加密备份，不能提交到 Git、音乐 ZIP 或 GitHub Release。

## 验证与清理

`npm test` 为单元测试。`scripts/smoke.cjs`、`check-playback.cjs`、`check-updates.cjs`、`check-existing-library.cjs` 使用独立测试曲库启动真实 Electron，不调用付费 AI。Playwright 路径可通过 PLAYWRIGHT_MODULE 指定，打包主程序通过 TINGYU_EXECUTABLE 指定。

`check-portable.cjs` 检查便携启动与 win-unpacked 载荷一致性；运行前需要重新构建该目录。历史迁移回归需使用 TINGYU_LEGACY_EXECUTABLE 提供另行保存的 v0.3.6 主程序，旧安装包不随仓库保存。

`scripts/clean-release-artifacts.ps1` 默认只预览，`-Apply` 才删除已识别的旧发行产物；执行前强制验证当前签名清单及三个安装包哈希，保护 Data、发布密钥和未知文件，拒绝链接及越界路径。不要用删除整个 release 文件夹代替它。
