# 在线音源 / 私人曲库（v1.0.4）

PC 与安卓在「偏好设置 → 在线音源 / 私人曲库」配置同一 HTTPS 曲库地址和访问密钥，点击「一键连接并自动上传」后，自动核对并上传当前本地库的全部音频、封面、原文歌词和已保存的中文译文。只扫描软件当前已打开的音乐库，不遍历任意磁盘或手机目录。升级旧配置不擅自开启，需要主动点击。不要把服务器 root 密码或 AI API Key 填到曲库密钥中。

## 使用流程

### 链接与密钥不是通用音源解析

音源链接可以在软件中自行修改，但目标必须部署兼容的弦栖霁在线曲库接口并提供可信 HTTPS。普通音乐分享网页、网盘链接、单首 MP3 地址或其他平台 API 不能直接当作此曲库地址；其他协议需要另行适配。修改输入框不会自动给对方网站增加接口或上传能力。

曲库访问密钥是对应服务器签发 / 授权的访问凭证，类似私人曲库的门禁卡，不是任意编写的文字，也不是 AI API Key、服务器 root 密码或通用音乐平台密钥。只读凭证允许读取和下载，读写凭证还允许上传与修订；随意填写不会取得权限。更换凭证需同步更新服务端授权，不能只修改软件输入框。

同一后端仅更换已正确配置的域名时，原凭证通常仍有效；更换后端则使用对方授权的凭证。不要向陌生服务器提交自己的写入凭证，目标服务器会收到请求中的访问密钥。曲库读写不触发 AI 请求；AI 翻译仍使用独立配置和主动调用流程。

### 实际操作

1. 填写链接与访问密钥，或导入管理员提供的 `.xqsource` / JSON 连接配置。导入只填入表单，不立即发送歌曲。确认地址后点击「一键连接并自动上传」开始全库核对；只想手动访问或使用只读密钥时点「保存并连接 / 刷新」。链接可改为后续的可信 HTTPS 域名，修改链接会清空表单内旧密钥，避免误发到新服务器。
2. 「线上曲库」展示歌名、歌手、是否有歌词 / 中文，支持搜索和多选。点击「下载 / 补充到本地」后再次确认，逐首校验并保存；播放使用本地音乐库，不是免下载的在线流播放。
3. 自动模式会上传当前库全部内容，显示已核对、已上传、相同、冲突和失败数。新增音频或保存联网歌词、AI 中文译文后自动排队上传；不另外调用 AI，不收集播放器配置、API Key 或播放历史。相同内容跳过，同 SHA-256 媒体不重复存储。只上传已保存内容，不自动联网生成缺失歌词或译文。
4. 自动模式可暂停；PC 关闭设置或隐藏到托盘仍运行（退出程序即停止），安卓锁屏 / 切后台暂停，回到前台后恢复，需要保持应用前台完成大曲库上传。断网后重试、重启后重新核对并从已确认块继续。每分钟及恢复联网时核对一次，也可点「立即核对」。
5. 切换音乐库、修改连接或手动传输前先暂停自动上传。仍可在「本地可上传」选中歌曲、再次确认后手动上传；自动冲突列表供核对，不强制覆盖。不会自动删除本地或线上歌曲，也不自动下载线上独有歌曲，下载仍需选择并确认。

首次连接时两端已有不同原文 / 时间轴、中文、封面或歌曲信息会保留两端并列为待处理。相同原文与时间下，一端缺失的中文可安全补入线上。成功同步且线上修订未变化时，本机后续保存的修订可自动上传；线上被其他设备改动时重新比对，保留不兼容的编辑。校验基准按当前曲库、服务器与密钥隔离。

同音频上传以本地提供的非空歌词为主更新；本地完全缺失的歌词、同时间与原文对应的缺失译文、未提供的封面保留线上已有内容。服务器保存每次元数据修订的历史版本。如果其他设备已更新同一首，拒绝覆盖，必须刷新后重新确认；没有“强制覆盖”按钮。来源音乐平台的私有、加密或 DRM 文件不作解密。

下载相同音频不覆盖本地歌词、已有中文、收藏和播放记录，只补充缺失内容；中文需原文与时间对应才填入。新音频 / 封面完整下载并 SHA-256 校验后保存，损坏或中断不覆盖本地歌曲。下载中断后该首需重试，已完成歌曲保留；单首文件仍受设备内存和剩余空间限制。

上传以 1 MiB 分块，每块落盘确认后保存服务端检查点。断网 / 暂停 / 重启后，再选择同歌曲、同元数据、同服务器与密钥，可从已确认的位置继续。修改歌词或目标地址会作为新任务。暂停需等待当前网络请求结束；在最终提交请求已经发送时暂停，可能已经提交成功，请刷新确认。尚未完成的上传不会出现在正式线上列表中。

## 密钥与隐私

- 只读密钥可浏览和下载；写入密钥可读取、上传与修订。不要公开写入密钥，也不要把它放在 URL 查询参数中。
- Windows 配置为应用 Data 下的 `online-source.json`，密钥使用 Windows DPAPI 加密；安卓配置为应用私有 `no_backup/config/online-source.json`，使用独立 Android Keystore AES-GCM 身份加密，与 AI 密钥隔离。不勾选记住时仅本次运行保存密钥，服务器地址可保留。
- 配置和密钥不进入音乐 ZIP 或文件音乐库。换设备后重新填写。应用更新包不包含你的曲库访问密钥。
- 客户端仅使用 HTTPS，拒绝携带用户名、密码、参数或片段的配置链接；带认证的请求禁止重定向，避免把密钥发往其他服务。
- 服务器仅存密钥的 SHA-256 摘要，随机密钥具有 256 位熵；所有歌曲与歌词 API 需要认证。服务仅监听本机回环，由现有 HTTPS Nginx 反代；不额外公开服务端口。

## 接口概览（schema 1）

以下路径相对配置的 HTTPS 根地址，全部发送 `Authorization: Bearer <曲库访问密钥>`。响应为 JSON，POST 使用 `Content-Type: application/json`。密钥不可放入 URL。

| 方法 / 路径 | 用途 |
| --- | --- |
| GET `info` | 产品协议、读写权限、歌曲数、分块大小 |
| GET `tracks?offset=0` | 分页歌曲信息，含 metadata、audio / cover 描述、revision、updatedAt；next 为后续偏移或 null |
| GET `tracks/{音频SHA256}` | 单曲信息与修订号 |
| GET `tracks/{音频SHA256}/media/{audio或cover}?offset=0&length=1048576` | 受认证保护的文件分块，以 Base64 返回并附文件指纹 / 长度 |
| POST `uploads` | 提交 metadata、audio / cover 的 SHA-256、长度、类型及 expectedRevision；不存在歌曲时修订为 0 |
| GET `uploads/{任务ID}` | 读取已确认的上传偏移 |
| POST `uploads/{任务ID}/chunk` | kind、offset、Base64 data，严格顺序写入并 fsync 后确认 |
| POST `uploads/{任务ID}/finish` | 校验完整媒体与预期修订号，事务提交新修订；重复 finish 不重复新增修订 |

常见状态：401 未认证，403 只读，409 检查点 / 版本冲突，413 请求过大，416 分块范围错误，422 内容哈希错误，507 服务端空间不足。单个 POST 限 2 MiB（1 MiB 二进制加 Base64 可容纳），这是服务安全限制，不是歌曲总大小限制。单首索引 JSON 限 1 MiB，分页约 4 MiB，避免错误数据耗尽服务内存。

## 服务维护

### 现有更新服务器一键部署

运行 `npm run source:package` 生成不含凭据或歌曲的 `release/v版本/Xianqiji-library-server-版本.tar.gz`，正式 GitHub Release 也附带该包。传到原服务器并解压后，在解压目录执行 `sudo bash install-library.sh`。

此入口复用此前已配置的 HTTPS / 宝塔 Nginx 更新站点（`/www/server/panel/vhost/nginx/xianqiji-updates.conf`），检查 Python 3.6+、创建非 root 服务、校验 Nginx 并重载；不会对陌生服务器盲目覆盖站点或放开端口。没有这套 HTTPS 站点时会停止，需要先独立完成 HTTPS 配置，再按自己的环境适配路径。

首次部署生成随机读写 / 只读密钥，认证服务仅保存摘要；连接文件另存 root 私有目录的 `/root/xianqiji-library-owner.xqsource` 和 `/root/xianqiji-library-reader.xqsource`。私下传到设备，通过软件「导入连接配置」选择 owner 文件，再点一键连接；只读文件可给有权访问的人，owner 文件不能公开。重复部署保留原摘要、媒体和数据库，不轮换密钥。原有部署没有明文连接文件时，使用维护者保留的凭据 JSON，不能从服务端摘要恢复明文。换域名后在表单或受保护的连接文件中填写实际可信地址。

在线核验检查服务器实际文件 SHA-256，文件状态不变时复用已核验结果，不反复下载整库。文件缺失 / 同长度内容损坏会被识别；本机有对应原文件时可重传修复，不能修复时列为失败。元数据并发修改仍以预期修订号作最终保护。`GET tracks/{音频SHA256}/verify` 返回 id、revision、ok 和各媒体校验状态；`GET info` 的 verification 为 true 才能使用自动上传。

部署代码为 `deployment/library-server.py`（Python 标准库 + SQLite）、`library.service`、`library-nginx-location.conf`、`provision-library.sh`。不安装第三方 Python 服务端依赖，不修改现有更新清单与安装包。服务以独立非 root 用户运行；SQLite 索引 / 元数据历史、媒体指纹文件和未完成上传分别保存在数据目录中。

备份应先停止在线曲库服务再完整复制数据目录与认证摘要文件（或使用 SQLite 在线备份 API），不要仅复制正在使用的 sqlite3 主文件而漏掉 WAL。媒体暂存与历史版本目前不自动删除，需监控磁盘空间；服务在剩余低于约 256 MiB 时拒绝继续写入。当前不提供远程删除歌曲或恢复历史的客户端按钮。

测试：`python deployment/test-library-server.py`，`npm test`；移动界面流程与原生 Keystore、目录授权、锁屏仍需手机实测。服务端事务行为参考 [Python SQLite 文档](https://docs.python.org/3/library/sqlite3.html)。本机真实地址、服务路径与凭据文件位置单独保存在不上传 Git 的部署记录中。
